## Timing and marginal quantities

The backward pass is `OWNC, RNTC → OWNH, RNTH → TENU → income expectation`: consumption, housing, tenure, then integration over income. See [whisperer.py, lines 618–716](../../../../examples/housing_renting/whisperer.py#L618) and its operator bindings at lines 147–155. These aliases correspond respectively to Bellman's `owner_cons`, `renter_cons`, `owner_housing`, `renter_housing`, `tenure_choice`.

Owners pay the transaction cost only when housing changes ([horses_h.py, lines 290–306](../../../../src/dcsmm/models/housing_renting/horses_h.py#L290)). Renters liquidate housing in TENU, receive income and pay rent in RNTH, and carry zero owned housing forward. Their consumption axis uses legacy `H_nxt` for services but selects owned-housing continuation index zero ([RNTC.yml, lines 99–105](../../../../examples/housing_renting/config_HR/STD_RES_SETTINGS_4_TAXES/stages/RNTC.yml#L99); [horses_c.py, lines 505–540](../../../../src/dcsmm/models/housing_renting/horses_c.py#L505)). Preserve this distinction.

**Marginal conversion is mandatory.** Existing discrete choices pass `lambda_` unchanged ([horses_h.py, line 319](../../../../src/dcsmm/models/housing_renting/horses_h.py#L319); [horses_t.py, line 163](../../../../src/dcsmm/models/housing_renting/horses_t.py#L163)); EGM multiplies it by `beta * delta * Rfree` ([horses_c.py, line 535](../../../../src/dcsmm/models/housing_renting/horses_c.py#L535)). Bellman instead includes `1+r−dT` in the asset derivative in [owner_housing.bl, line 41](/Users/akshayshanker/Research/Repos/bellman-ddsl/applications/housing-renting/owner_housing.bl#L41) and [tenure_choice.bl, line 45](/Users/akshayshanker/Research/Repos/bellman-ddsl/applications/housing-renting/tenure_choice.bl#L45), then uses `β*dV` in [owner_cons.bl, line 37](/Users/akshayshanker/Research/Repos/bellman-ddsl/applications/housing-renting/owner_cons.bl#L37). Direct substitution double-counts the return. Specify one conversion or change the EGM scaling explicitly. Separately check terminal scaling against terminal `u_c(a,H)` initialization ([whisperer.py, lines 395–397](../../../../examples/housing_renting/whisperer.py#L395)).

FUES stores calendar periods chronologically and solves them in reverse ([whisperer.py, line 588](../../../../examples/housing_renting/whisperer.py#L588)); Bellman's trellis is terminal-first. Translate indices explicitly, preserving reported period 0 and terminal-period timing exclusions.

## Economic differences and missing prerequisites

Present bias is substantive: when `delta_pb < 1`, choices maximize Q while forwarding lifetime value, with a policy-gradient adjustment to the marginal ([horses_t.py, lines 99–163](../../../../src/dcsmm/models/housing_renting/horses_t.py#L99); [horses_c.py, lines 721–742](../../../../src/dcsmm/models/housing_renting/horses_c.py#L721)). Existing Bellman housing files contain only exponential discounting. Preserve this case through an explicit specification or limit the first accepted migration to `delta_pb=1`; do not claim all configurations migrated.

Bellman's [calibration.yml, lines 46–54](/Users/akshayshanker/Research/Repos/bellman-ddsl/applications/housing-renting/calibration.yml#L46) omits the income matrix and levels because their domains are unavailable. FUES uses a 49-state chain. Verify post-release calibration support and branch assembly: [trellis.yml, line 32](/Users/akshayshanker/Research/Repos/bellman-ddsl/applications/housing-renting/trellis.yml#L32) gives two sources for each next-period arrival field. The same file documents terminal data only in prose (lines 16–25), and contains one period. Parsing tests do not establish numerical execution.

## Independent probes and baseline variants

CPU utility uses `log(kappa*(H+iota))` ([STD master.yml, lines 614–631](../../../../examples/housing_renting/config_HR/STD_RES_SETTINGS_4_TAXES/master.yml#L614)); GPU uses `log(kappa*H+iota)` ([horses_c_gpu.py, lines 70 and 206](../../../../src/dcsmm/models/housing_renting/horses_c_gpu.py#L70)). With α=.77, κ=.075 and ι=.01, direct evaluation gives GPU-minus-CPU utility **0.5957614481 at H=0**, **0.0264989468 at H=1**. This varies with housing and can change choices. Record a separate correction decision before treating GPU results as a migration reference. Numba-friendly CPU functions do not establish CUDA compatibility.

A probe executed only the undecorated [tax scalar source, lines 112–129](../../../../examples/housing_renting/helpers/asset_tax.py#L112). At assets 6.97, `test_0.4` gives **0.05**, while `STD_RES_SETTINGS_4_TAXES` gives **0.18852**. The former marks the preceding bracket open; the latter matches it first despite the following bracket being left-closed. Bellman's strict-step schedule gives 0.18852. Preserve variant-specific endpoint precedence and [threshold snapping, lines 261–327](../../../../examples/housing_renting/helpers/asset_tax.py#L261), which also recalculates tax intercepts.
