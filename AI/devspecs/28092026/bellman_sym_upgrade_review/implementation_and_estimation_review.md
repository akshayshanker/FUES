Reviewed the [pre-upgrade specification](../bellman_sym_upgrade.md) and its four supporting reviews using [econ-model-maker](/Users/akshayshanker/Research/Repos/comp-econ-aeons/aeons/econ-model-maker/SKILL.md) and [structural-model-estimation](/Users/akshayshanker/Research/Repos/comp-econ-aeons/aeons/structural-model-estimation/SKILL.md). ## Corrections

1. **High priority — Define the criterion and distinguish a successful evaluation from a penalty.** Expand acceptance item 5 with the resolved target columns, model-variable mapping, units, age rows, sample restrictions, missing-data rule and weights. The current `[40,44]` age group selects 40–43; level moments require the existing conversion to Australian dollars. The default weight changes at absolute target value 1: the probe's identical 10% proportional error scores `0.01` in one unit scale and `0.0001` in another. Record this rule explicitly, rather than claiming unit invariance. A trial exception returns the finite loss `1e10`; an absent simulated target returns `1e6`. Neither establishes a successful solve or simulation. Require recorded evaluation status for solver and moment failures, including the existing tiny serial/distributed checks. Known infeasible draws may retain explicit penalties; unexpected errors must remain visible. Add a synthetic-panel comparison of every contribution between kikku and asva, including missing and nonfinite moments. See [criterion](/Users/akshayshanker/Research/Repos/FUES2026/kikku/kikku/run/estimate.py:99) and the [observed arithmetic](evidence/skill_review_probes.txt).

2. **High priority — Make best-estimate reconstruction a verified prerequisite.** At implementation §4, explicitly inherit the active estimation brief's [equality requirement](/Users/akshayshanker/Research/Repos/FUES2026/FUES/AI/devspecs/28092026/cd_estimation_and_postprocess.md:363) and [saved-output acceptance](/Users/akshayshanker/Research/Repos/FUES2026/FUES/AI/devspecs/28092026/cd_estimation_and_postprocess.md:764). They already require fit evaluated at `theta_best`; do not treat the unfinished implementation as authoritative. Its current [fit function](/Users/akshayshanker/Research/Repos/FUES2026/FUES-wt-cd-estimation/examples/durables/postprocess/at_estimates.py:395) drops absent simulated keys: the probe returns criterion **1,000,000.01**, but reconstructed contributions **0.01**. Require all target contributions, including penalties, or reject incomplete reconstruction. Check a deliberately different final candidate followed by a fresh best-parameter evaluation. Extend the existing persistence requirement to the estimation YAML, target CSV, bounds, type rules/shares/order and resolved overrides; preserve contents or verify hashes before rereading them. A changed copied CSV/type rule must reproduce from recorded inputs or be refused. These are final-merge prerequisites, not instructions to edit the concurrent branch now.

3. **Medium priority — Specify how raw keeper candidates will be recorded.** Implementation §1 and acceptance item 4 require arrays before upper-envelope refinement, but the actual [fast path](/Users/akshayshanker/Research/Repos/FUES2026/FUES/examples/durables/solvers/keeper_egm.py:55) returns `cntn_data=None`. The [generic diagnostic output](/Users/akshayshanker/Research/Repos/FUES2026/FUES/examples/durables/solvers/keeper_egm.py:395) stores refined arrays. Switching methods also changes constrained padding from `max(2,n_a//10)` to `n_a`; it cannot characterize the executed fast path. Add a bounded diagnostic capture of that path's pre-refinement arrays, preserving its calculation and final result interface. Record candidates and selected branches before and after migration; exclude diagnostic capture from performance measurements. Do not describe existing refined arrays as raw candidates.

4. **Medium priority — Add concrete contracts for changed numerical adapters.** Beside implementation §3, tabulate only changed callbacks: signature, input/output order, axes, dtype, grid coordinates and discount/transition factors. Durables [keeper/tenure arrays](/Users/akshayshanker/Research/Repos/FUES2026/FUES/examples/durables/docs/solution_scheme.md:64) have axes `(n_z,n_a,n_h)`; adjuster arrays have `(n_z,n_w)`. Housing [continuation arrays](/Users/akshayshanker/Research/Repos/FUES2026/FUES/src/dcsmm/models/housing_renting/horses_c.py:528) use the next-asset grid and a renter housing-index mapping, not the evaluation-grid length. Retain the reviews' distinct discount conventions and shock timing. Check unequal grid lengths, a nonsymmetric two-state transition matrix, and independent binding of two period occurrences. Specify a FUES-owned, per-grid derived tax table: [current code](/Users/akshayshanker/Research/Repos/FUES2026/FUES/src/dcsmm/models/housing_renting/horses_c.py:404) stores `_snapped_to_grid` in settings. Never mutate Bellman's authored table or reuse a snapped table after changing its grid.

5. **Medium priority — Give each comparison an independent reference and a justified tolerance.** Replace adoption of [generic proposed tolerances](shared.md:68) as sufficient evidence with a small per-example comparison table: reference equation/calculation, quantity, norm, region, boundary convention and reason for the tolerance. Use a hand-calculated expectation for two nonsymmetric states, a terminal identity, or an independently evaluated objective; do not reuse the changed production transition/interpolator to certify that component. Existing-characterization checks pass before and after; no artificial failing test is needed for a preservation refactor. Narrow [parameter-sensitivity wording](shared.md:72) to binding and measured responses: evaluate θ₀ → θ₁ → θ₀ with common draws, compare a parameter-dependent primitive with its formula, and compare repeated θ₀ with fresh construction. A tiny-grid policy need not change for every parameter change. These checks establish neither statistical identification nor valid sampling standard errors.

6. **Medium priority — Add the constrained worker-value discrepancy to the retirement account.** The [existing arrival operator](/Users/akshayshanker/Research/Repos/FUES2026/FUES/examples/retirement/solvers/operators.py:149) records consumption `w − grid[0]` but evaluates current utility at `w`. With logarithmic utility, resources 1 and saving floor 0.2, the current-utility difference is **0.2231435513**; common continuation/work-cost terms cancel. The tiny default floor masks this discrepancy. Add it to retirement's named pre-existing behaviours, with a non-negligible-floor comparison. Keep any correction separate from the dependency migration. The probe checks the two formulas, not reachability of this branch in a full solve.
